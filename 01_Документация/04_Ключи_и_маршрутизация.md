# Ключи и маршрутизация провайдеров

Все ключи и маршруты настраиваются в `Global Variables` внутри Streamer.bot.

Базовый action для создания переменных:
- [InitGlobals.cs](../02_Стримербот_и_CSharp/02_Экшены_и_ядро/InitGlobals.cs)

## Что принято как база
- `TTS по умолчанию`: `Inworld`
- `Картинки по умолчанию`: `flux-kontext-max` через `Fireworks`
- `Текстовые модели`: меняются через глобалки по задачам, без хардкода в логике
- `Fireworks reasoning`: по умолчанию выключен там, где он не нужен

## Обязательные ключи

### Для текста
- `OpenRouterKey`
- `FireworksKey`

### Для TTS
- `InworldTTSAuth`
- `NttsApiKey`
- `FishAudioApiKey`

### Для картинок
- `FireworksKey`

### Для OBS runtime
- `VisualRuntimeEndpoint`
  - рекомендуемое значение: `http://127.0.0.1:1608/events`

## TTS-маршрут

Главный action:
- [InworldTTS.cs](../02_Стримербот_и_CSharp/02_Экшены_и_ядро/InworldTTS.cs)

Порядок теперь задаётся глобалками:
- `TtsProviderPrimary`
- `TtsProviderSecondary`
- `TtsProviderTertiary`

Текущая рекомендуемая база:

```text
TtsProviderPrimary=inworld
TtsProviderSecondary=ntts
TtsProviderTertiary=fish
```

Если `ntts` явно стоит вторым или третьим в маршруте, он будет использоваться как нормальный fallback.
`NttsMixPct` тогда уже не мешает и не делает выбор случайным.

### Настройки Inworld
- `InworldModelId`
- `InworldVoiceId`
- `InworldAudioEncoding`
- `InworldSampleRateHertz`
- `InworldSpeakingRate`

Рекомендуемые значения:

```text
InworldModelId=inworld-tts-1.5-max
InworldVoiceId=default-mtpxxj7uhgk_xn4yzgz4aq__chitani
InworldAudioEncoding=LINEAR16
InworldSampleRateHertz=22050
InworldSpeakingRate=1.0
```

### Голоса под персонажей
Можно задавать отдельный голос для каждой персоны без переписывания кода:

```text
Persona_Skuf_InworldVoiceId=...
Persona_Toxic_InworldVoiceId=...
Persona_UwU_InworldVoiceId=...
Persona_Mistress_InworldVoiceId=...
```

Если у персоны есть свой `Persona_<Имя>_InworldVoiceId`, action возьмёт его.
Если нет, возьмёт общий `InworldVoiceId`.

## Текстовые модели по задачам

### Глобальные дефолты
- `OpenRouterDefaultTextModel`
- `FireworksDefaultTextModel`

### По отдельным задачам
- `ChatBotProvider`
- `ChatBotModel`
- `ModProvider`
- `ModModel`
- `ModResponseProvider`
- `ModResponseModel`
- `OracleProvider`
- `OracleModel`
- `DonationProvider`
- `DonationModel`
- `StreamRecapProvider`
- `StreamRecapModel`

### Рекомендуемая стартовая схема

```text
LlmProvider=openrouter
OpenRouterDefaultTextModel=xiaomi/mimo-v2-flash
FireworksDefaultTextModel=accounts/fireworks/models/kimi-k2-instruct-0905

ChatBotProvider=openrouter
ChatBotModel=xiaomi/mimo-v2-flash

ModProvider=openrouter
ModModel=google/gemini-2.0-flash-001

ModResponseProvider=openrouter
ModResponseModel=google/gemini-2.0-flash-001

OracleProvider=openrouter
OracleModel=xiaomi/mimo-v2-flash

DonationProvider=openrouter
DonationModel=xiaomi/mimo-v2-flash

StreamRecapProvider=openrouter
StreamRecapModel=xiaomi/mimo-v2-flash
```

Если захочешь быстро перевести конкретную задачу на Fireworks, меняешь только её пару:

```text
OracleProvider=fireworks
OracleModel=accounts/fireworks/models/kimi-k2-instruct-0905
```

## Мета-поведение чат-бота

Теперь у обычного чат-бота есть отдельное состояние отношений по каждому зрителю.

Главные глобалки:
- `ChatBotRelationshipEnabled`
- `ChatBotMemorySize`
- `ChatBotRelationshipDecayMinutes`
- `ChatBotAllowSpicyRoasts`
- `ViewerRelationshipState`

Рекомендуемая база:

```text
ChatBotRelationshipEnabled=true
ChatBotMemorySize=5
ChatBotRelationshipDecayMinutes=30
ChatBotAllowSpicyRoasts=true
```

Что это значит:
- бот хранит последние `5` сообщений на конкретного зрителя
- копит `annoyance`, `affection`, `respect`, `familiarity`
- всегда отвечает, но меняет тон
- если зритель утомляет, бот становится суше, язвительнее и может безопасно подколоть

Важно:
- это не бан-система и не игнор
- бот всё равно отвечает
- "обзывательства" только в безопасном шоу-формате, без hate speech, без реальных slur-слов и без угроз

## Картинки

Главный action:
- [ChannelPointImage.cs](../02_Стримербот_и_CSharp/02_Экшены_и_ядро/ChannelPointImage.cs)

### Что важно
- `ImageGenerationProvider`
- `ImageGenerationModel`
- `ImageGenerationWorkflowUrl`
- `ImageRefineProvider`
- `ImageRefineModel`
- `ImageReactionProvider`

Рекомендуемая база:

```text
ImageGenerationProvider=fireworks
ImageGenerationModel=accounts/fireworks/models/flux-kontext-max
ImageGenerationWorkflowUrl=https://api.fireworks.ai/inference/v1/workflows/accounts/fireworks/models/flux-kontext-max

ImageRefineProvider=openrouter
ImageRefineModel=google/gemini-2.0-flash-001

ImageReactionProvider=fireworks
ImageReactionFireworksModel=accounts/fireworks/models/kimi-k2p5
ImageReactionOpenRouterModel=google/gemini-2.0-flash-001
```

## Fireworks reasoning

Если используешь Fireworks, reasoning лучше включать только там, где он реально нужен.

Сейчас рекомендуемая база такая:

```text
ChatBotReasoningEffort=none
OracleReasoningEffort=none
ImageRefineReasoningEffort=none
ImageReactionReasoningEffort=none
ImageReactionFallbackReasoningEffort=none
```

Это сделано специально, чтобы Fireworks не начинал "думать вслух" там, где нужен короткий и чистый результат.

## Готовые рабочие схемы

### Самая практичная

```text
TtsProviderPrimary=inworld
TtsProviderSecondary=ntts
TtsProviderTertiary=fish

LlmProvider=openrouter
ChatBotProvider=openrouter
ModProvider=openrouter
OracleProvider=openrouter
StreamRecapProvider=openrouter

ImageGenerationProvider=fireworks
ImageGenerationModel=accounts/fireworks/models/flux-kontext-max
ImageReactionProvider=fireworks
```

### Если хочется Oracle на Fireworks, а всё остальное оставить как есть

```text
OracleProvider=fireworks
OracleModel=accounts/fireworks/models/kimi-k2-instruct-0905
OracleReasoningEffort=none
```
