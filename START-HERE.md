# Streamer OS — начать здесь

Streamer OS связывает Streamer.bot, OBS, AI-персоны, донаты, генерацию картинок и озвучку. После первой настройки запуск — через `start-streamer-os.cmd`, настройки — в браузере.

## 1. Установить файлы

Нужны Windows x64, OBS Studio с Qt 6 и актуальный Streamer.bot с поддержкой C# 11+. Если используешь исходники, сначала собери [OBS-плагин](03_OBS_и_аудио/01_Плагин_OBS/obs-plugin/README_BUILD.md), затем запусти `package.ps1`. Готовый пакет опубликован в [Releases](https://github.com/Kiwunaka/streamer-os/releases).

В распакованном пакете:

1. Закрой OBS. Скопируй содержимое папки `OBS` в корень установки OBS, обычно `C:\Program Files\obs-studio`. Папки `obs-plugins` и `data` должны объединиться с существующими.
2. Папку `Streamer.bot` из пакета сохрани рядом со своим Streamer.bot в отдельный каталог со скриптами. Не заменяй ею программу Streamer.bot.
3. Запусти OBS. Открой **Tools → Streamer OS Runtime**. Во вкладке **Server** выбери устройство вывода, оставь **Start runtime with OBS** включённым. Во вкладке **Runtime** создай браузерный источник кнопкой **Insert Runtime** для нужной сцены.
4. Если док не появился, проверь журнал OBS: DLL должна подходить к версии OBS/Qt. Не копируй случайные Qt DLL в OBS; при несовпадении пересобери плагин под свою версию.

Старый Python/Lua AudioViz одновременно не запускай: он занимает те же порты и не обслуживает новую панель.

## 2. Создать действия Streamer.bot

Каждый исходник `CPHInline` — отдельное поддействие **Execute C# Code**. Вставь код, открой **References**, добавь нужные библиотеки и нажми **Compile**.

| Имя действия, точно как написано | Исходник | Назначение |
| --- | --- | --- |
| `Streamer OS | Init` | `InitGlobals.cs` | Запустить один раз с `force=false` |
| `Streamer OS | Settings` | `StreamerOsSettings.cs` | Сохранение из web-панели; отдельная очередь, не занятая генерацией |
| `Streamer OS | Check` | `StartupHealthCheck.cs` | Проверка наличия ключей и OBS runtime без платных запросов |
| `TTS` | `InworldTTS.cs` | Общая озвучка; входной аргумент `rawInput` |
| `AI | Donation` | `AiDonationHandler.cs` | Реакция на донат |
| `AI | Image` | `ChannelPointImage.cs` | Картинка по награде; вход `prompt` или `rawInput` |
| `AI | Persona` | `AiPersonaSwitcher.cs` | Смена персоны; аргумент `style`: `skuf`, `toxic`, `uwu`, `mistress` |

В пакете эти файлы лежат в `Streamer.bot`. В репозитории — в `02_Стримербот_и_CSharp/01_Персоны_и_донаты` и `02_Экшены_и_ядро`.

Для **TTS, AI | Donation, AI | Image** добавь в References файл **StreamerOs.Shared.dll** из пакета. Для остальных скриптов с JSON нужен `Newtonsoft.Json.dll` из установки Streamer.bot; для HTTP — `System.Net.Http`. Не вставляй файлы SharedCore как самостоятельные действия.

Все действия, которые меняют историю донатов, инвентари и дуэли, выполняй в одной последовательной blocking-очереди: так параллельные события не затрут состояние друг друга. Настройки держи в отдельной очереди. Для TTS выдели последовательную очередь, чтобы голоса не накладывались.

Готового `.sb`-экспорта в исходных наработках нет. Первый набор действий создаётся вручную; панель не создаёт действия сама.

## 3. Открыть web-панель

1. В Streamer.bot: **Servers / Clients → WebSocket Server**. Адрес `127.0.0.1`, порт `8080`, включи **Authentication**, задай пароль и запусти сервер. Для повторных запусков включи автозапуск сервера в Streamer.bot.
2. Запусти `Streamer OS | Init` с `force=false`. Существующие значения сохранятся; два удалённых из каталога ID моделей будут заменены на актуальные значения по умолчанию.
3. Открой [http://127.0.0.1:1608/admin](http://127.0.0.1:1608/admin), введи пароль WebSocket и нажми **Подключить**.
4. Заполни ключи нужных сервисов, модели и голоса. Нажми **Сохранить изменения**. Настройки хранятся в постоянных глобальных переменных Streamer.bot; в браузере они не сохраняются.
5. Нажми **Показать тест на экране**, затем **Проверить настройки**. Вторая кнопка показывает результат в журнале Streamer.bot и в runtime. Для пробы голоса есть отдельная кнопка **Озвучить · платный API**.

Подробно о ключах, голосах и ценах запросов — [ключи и маршрутизация](01_Документация/04_Ключи_и_маршрутизация.md). Для минимального старта хватит одного текстового провайдера, одного TTS и генератора изображений, если нужны картинки. Неиспользуемые позиции TTS поставь в `none`.

## 4. Запуск каждый день

Дважды щёлкни `start-streamer-os.cmd`. При первом запуске выбери `obs64.exe` и `Streamer.bot.exe`. Скрипт запомнит только пути в локальном `launcher.local.json`, запустит приложения и откроет панель после ответа OBS. Уже запущенные приложения повторно не запускаются.

Чтобы выбрать пути заново: `start-streamer-os.cmd -ResetPaths`. Запуск не устанавливает плагин и не заменяет первую настройку действий.

## 5. Подключить донаты, мемы и чат

- DonationAlerts / MemeAlerts: [коннекторы и инструкции](https://github.com/Kiwunaka/streamer.bot-donationAlerts), [получение maClientId / maClientSecret](https://github.com/Kiwunaka/streamer.bot-donationAlerts/blob/main/docs/MEMEALERTS.md).
- Аргументы донатов, команды и остальные модули: [карта проекта](01_Документация/07_Карта_проекта.md), [настройка Streamer.bot](01_Документация/03_Настройка_Streamer_bot.md).
- Подключай один основной оверлей для доната: новый Visual Runtime или прежний Donation Overlay. Два одновременно продублируют картинку и звук.

## Если не работает

| Симптом | Что проверить |
| --- | --- |
| Не открывается `/admin` | OBS запущен, док Runtime → Server работает, файлы admin.html/js/css установлены, порт 1608 свободен |
| Панель не подключается | WebSocket Server запущен, адрес/порт верны, Authentication включён, пароль совпадает |
| Нет подтверждения сохранения | Действие `Streamer OS | Settings` существует, включено, Compile прошёл; его очередь не заблокирована |
| Ключ задан, но ответ 401/403 | Ключ принадлежит нужному сервису, разрешения и баланс доступны; Inworld требует полный `Basic …` |
| TTS молчит | Выбран провайдер, заполнен voice/reference ID, действие `TTS` скомпилировано с Shared DLL; проверь аудиовывод Streamer.bot |
| Платный запрос завис/истёк таймаут | Проверь журнал и кабинет провайдера перед повтором: таймаут не означает, что генерация не была оплачена |
| Изображение есть в журнале, но не в OBS | В сцене есть источник Visual Runtime, он видим и не перекрыт другими источниками |

Перед первым эфиром проверь реальные триггеры и звук на тестовой сцене. Сборка и локальные проверки не подтверждают доступность платных API для твоего аккаунта.
